# 首板验证与诊断固件

本文件定义未来样机如何验收。当前仅有文件与图纸，下面各项**均未实测**。编译通过、器件响应或串口中的某一个 PASS 不代表整机可用。

## 测量位置

[probe-map.svg](probe-map.svg) 分别画出两板正反面；[坐标表](probe-map.csv) 和 [来源 SHA](probe-map.json) 从实际 PCB 导出。M1 等编号是文档编号，指现有元件端子，并未在 PCB 新增测试焊盘；探针接触空间须由操作者确认，必要时在装壳前接短测量线。

| 信号 | 位置 | 验收要求 |
| --- | --- | --- |
| USB_VBUS | M1 / C15.1 | 本项目用连接器端 4.75、5.00、5.25V 三档受控输入验证；这是工程测试范围 |
| 系统 5V | M2 / C20.1 | CP2102 REGIN 工作范围为 4.0–5.25V；检查启动和负载瞬态，不以 5.5V 当允许工作值 |
| CP_VDD | M3 / C18.1 | 稳态 3.0–3.6V；按原厂 VDD ramp 定义，VDD 自身开始爬升至 2.7V 不超过 1ms，保存原始波形与起点定义；不从 USB 插入事件计入 ON 延迟，也不以 10–90% 典型估算替代 |
| 3V3、3V3A | M4 / C13.1，M5 / C4.2 | 稳态项目目标 3.135–3.465V（工程 ±5%），工作瞬态保持芯片要求的 3.0–3.6V |
| MCU EN | M6 / C7.1 | 启动稳定后释放；自动下载/reset 时序与供电波形一起记录 |
| GND | M7 / C20.2 | 示波器使用短接地弹簧，先确认与输入电源共地 |
| CC1、CC2 | M8 / R12.1，M9 / R13.1 | 断电分别核独立 5.1kΩ Rd；USB-C 两种方向分别测枚举与热插拔 |
| 显示板 5V / 3V3 | E1 / C3.1，E2 / C1.1 | 与主板同时测，包含真实排线压降与背光负载 |
| 背光电流 | E3 / R2.1 对 E4 / R2.2 | 测 R2 两端电压和实际电阻，按 I=V/R 求电流；不能从 PWM 百分比推算瞬时电流 |

CP2102 限值来自 [Silicon Labs CP2102/9 Rev1.8 Tables3/5/6](https://www.silabs.com/documents/public/data-sheets/CP2102-9.pdf)；MCU 电源范围来自 [Espressif PICO 系列 Table17](https://documentation.espressif.com/esp32-pico_series_datasheet_en.html)。3V3 稳态 ±5%、三档输入及下述重复次数是本项目的首板筛查要求，并非厂家认证测试。

不要用普通探头直接测 C16 的 100pF CT 节点来代替 CP_VDD 波形；探头电容会改变该时间常数。BUCK_SW 也不是稳压输出测点。

## 上电与记录顺序

1. 先核 PCB/装配版本及器件方向，记录裸板、装配板、屏幕和线缆照片。保持断电，核对 5V/3V3/GND、USB 及 FFC 的无误装/桥连情况；线缆导通用 [FFC 定义](FFC-CABLE-SPEC.md) 的独立被动夹具判据。
2. 先不接屏幕、排线和 SD，用限流实验电源从 USB_VBUS 输入端供电。低限流仅用于排除装配短路，不把限流导致的反复复位当成固件失败；确认电压与无异常温升后再按实际负载调整，记录限流设定与入口电流。不得向 CP_VDD 或 3V3 输出反向灌电。
3. 首次确认 M1–M6 的静态值和启动波形。输入每档重复冷启动及 USB 两种方向插入各 10 次，保存 CP_VDD、VDD_5V、3V3A 波形、枚举记录及是否复位。不能只填“看起来正常”。
4. 接入已核对的屏幕和排线，背光先保持关闭。测背光调节全范围的导通电流、稳态温升和电源范围；P133H002 的总背光电流不得超过其已引用规格书的 40mA 最大值，约 24mA 只是典型估算。没有电流结果时不以全亮画面代替验收。
5. 使用下述诊断固件做局部功能检查，再换回正式 `naive` 固件验证界面、SD 资源、传感器和网络。10MHz 显示仍需在屏端实测时序、过冲与振铃；软件时钟设定不等于接收端波形已通过。
6. 最终外壳、棱镜、背胶、排线均装好后，做至少 30 分钟 SD/WiFi/显示并发运行并记录重启计数、错误、温升及画面。环境/温度范围须按实际用途另行约定；这不是完整可靠性认证。
7. 天线需在最终叠层和闭壳状态下完成匹配及无线性能测试。`wifi-scan`、连接成功和 RSSI 都不能代替 VNA/天线匹配结果；由测试方记录测试夹具、校准面、频段和所用验收指标。

## 独立诊断固件

新增 `naive-bringup` 环境，不改变默认 `naive` 固件。只有明确选择此环境才编译诊断入口；程序默认关闭背光，不自动访问 SD 或联网。板上供电测试应先于烧录。

```sh
pio run -d 2.Firmware/HoloCubic-fw -e naive-bringup
# 有实物、供电检查通过并选定串口后，由操作者执行：
pio run -d 2.Firmware/HoloCubic-fw -e naive-bringup -t upload --upload-port <串口>
pio device monitor -d 2.Firmware/HoloCubic-fw -e naive-bringup --port <串口> -b 115200
```

每条命令用换行结束。超过 95 字符的输入整行拒绝。

| 命令 | 实际动作与结果边界 |
| --- | --- |
| `status` | 芯片修订、Flash、SDK 和配置；始终明确外部装配/波形/温升/RF 未验证 |
| `i2c` | 检查 MPU WHO_AM_I/14 字节数据和 BH1750 读取；改变姿态和光照反复比对，ACK 不等于校准合格 |
| `display` | 发送 RGB 条纹和四角编号；保持正式固件相同的镜像设置，需人工通过棱镜确认画面、方向和缺线 |
| `backlight 0..100` | 设置 GPIO5 反相 PWM；没有测量电流或温度的能力 |
| `rgb` | 低亮度依次发送红/绿/蓝，随后关闭；必须人工确认实物颜色 |
| `sd-status` | 按 GPIO14/26/13/15 和 4MHz 挂卡，报告容量和类型 |
| `sd-test` | 仅当 `/holocubic-bringup.bin` 不存在时新建 64KiB 文件，逐块写读比对并删除；存在则拒绝，不覆盖用户文件 |
| `wifi-scan` | 同步扫描并报告数量/最强 RSSI，不打印网络名称；扫描接口成功不代表天线合格 |
| `wifi-load` | 读取 SD `/wifi.txt` 前两行作为测试 AP 凭据，连接最长等待 15s，连接后同时读 SD/刷新屏幕 10s；不打印凭据、不做 HTTP 请求，结束断开 |

`wifi-load` 只验证本地功能冒烟，不产生持续网络吞吐负载，不能代替功耗最坏工况、丢包率或 RF 测试。恢复正式程序使用 `-e naive` 重新烧录。当前诊断固件仅完成编译与代码检查，尚未在板上执行。

## 交回的实际证据

每份记录注明操作者、板号、PCB/固件 SHA、物料批次、仪器/探头、供电、环境条件、原始附件及结论。用 [measurement-record.csv](measurement-record.csv) 填真实读数，保留原始波形/照片/串口日志。没有样机或没有测量的项目保持 `NOT_TESTED`，不要填 0、N/A 或用其他项目的 PASS 替代。
